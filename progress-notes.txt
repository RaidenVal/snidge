## 新机器快速上手（复制粘贴用）

需要安装：
  - Node.js LTS（https://nodejs.org）
  - Git（https://git-scm.com）

然后运行：

  git clone https://github.com/RaidenVal/snidge.git
  cd snidge
  npm install
  npm run dev

screenshot-helper.exe 已包含在 repo 里，不需要单独装 .NET SDK。

## 截图延迟修复（本次重点）

### 根因
Windows 上 Electron 的 desktopCapturer.getSources() 慢，是 Chromium 内部 IPC
和编码开销，不是硬件问题。Mac 完全没有这个问题。

### 各方案实测（3440×1440 显示器，100% DPI）

  desktopCapturer（原始）   screenshot: 478ms   总延迟: ~590ms
  Helper binary + PNG        screenshot: ~220ms  总延迟: ~330ms  ← 当前
  Helper binary + 原始BGRA   screenshot: ~290ms  总延迟: ~400ms  （pipe 传输量大，反而慢）

### 当前实现
  文件：resources/win/screenshot-helper.exe（12.5MB，单文件自包含）
  源码：tools/screenshot-helper/Program.cs
  语言：C# .NET 10，GDI CopyFromScreen + PNG 输出到 stdout
  集成：main/index.ts 里 triggerCapture()，Windows 走 helper，其他平台保留
        desktopCapturer

### 下一步优化（明天试）
  并行 spawn 方案，预计总延迟可降到 ~200ms：
  - 当前：hide 窗口 → 等 100ms → spawn helper → 截图（串行，共 330ms）
  - 优化：hide 窗口 → 立刻 spawn helper → helper 内部等 ~80ms → 截图（并行）
  - 改动：C# 加 --delay 参数；Electron 侧去掉显式 100ms 等待
  - 注意：delay 值要在实机调，太短会出现窗口残影
